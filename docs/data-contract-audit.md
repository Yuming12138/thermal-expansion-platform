## 2. 平台存在两条互不交叉的数据链路

这是理解全部量纲问题的关键。两条链路使用**不同来源、不同单位、不同语义**的热膨胀数据，且**从不互相换算**：

### 链路 A：目录检索（`nte-candidates-6701-v1-1`）

| 环节 | 位置 |
|---|---|
| 排序 | `catalog/queries.py:176, 253`（`sort_by=CTE_ppm`） |
| 区间筛选 | `catalog/queries.py:255-256` |
| 材料对比 | `catalog/queries.py:501` |
| 报告输出 | `reports/material_report.py:117` |

消费的字段是 **`CTE_ppm`（ppm/K，标量）**。

### 链路 B：ZTE 设计（`pte-reference-185-v1` + NTE 曲线）

| 环节 | 位置 |
|---|---|
| 曲线查询 | `composites/material_pair.py:29-58`（按 `release_slug` 过滤，取每材料最新成功曲线） |
| 曲线插值 | `composites/material_pair.py:60`（`alpha * 1_000_000` 转 ppm/K） |
| 配比优化 | `composites/curve_rom.py`、`screening.py` |

消费的字段是 **QHA 曲线（1/K）**，`api/app.py:605,792` 的导出表头明确自述为
`volumetric_thermal_expansion_coefficient_1_per_K`，即**体积**热膨胀系数 α_V。

### 两条链路不交叉 → 不存在单位混用

`TE_300K` 在整个代码库中的出现位置仅两处：

- `catalog/importer.py:32` —— 单位元数据标注 `"1/K"`
- `web/app.js:758` —— 展示用字段名列表

**它从未参与任何计算。** 因此标注为 `1/K`（实际量级为 ppm/K）只是一个展示层缺陷，不会污染任何计算结果。此前我推测的"10⁶ 混用风险"经完整追踪后**予以撤回**。

## 3. 真实缺口：体积膨胀与线膨胀从未定义

这是比 `TE_300K` 标注严重得多的问题，因为它**影响物理解释**。

**已知**：曲线侧是体积量 α_V（`app.py:605,792` 自述，且与 Phonopy QHA 的输出语义一致）。

**未知**：`CTE_ppm` 是体积膨胀还是线膨胀？全仓库检索无任何定义——

- `datasets/README.md`：只说明版本、来源路径与发布约定，未定义字段语义
- `datasets/manifests/*.json`：`property_provenance` 只覆盖 `G_GPa`、`E_tilde_GPa`、`full_elastic_tensor`，**未覆盖任何热膨胀字段**
- `datasets/schema/nte_candidates_v1.schema.json`：只声明类型为 `["number","null"]`，无语义
- `docs/`：全目录检索无"体积膨胀""线膨胀"相关表述

**后果**：

1. 同一材料在检索页显示的 `CTE_ppm` 与在 ZTE 页从曲线读出的 `alpha_300k_ppm_per_k`，若 `CTE_ppm` 是线膨胀，两者将相差约 **3 倍**，用户会看到两个不一致的数字而无从判断。
2. ZTE 容差 `zte_tolerance_ppm_per_k` 直接与体积量 α_V 比较。若用户按线膨胀的直觉设定容差（例如 ±1 ppm/K），实际相当于线膨胀 ±0.33 ppm/K，**容差语义偏宽松 3 倍**。

## 4. 决定性验证方法（需 catalog 数据库）

对**同时具备** `CTE_ppm` 与 QHA 曲线的材料，比较二者在 300 K 的取值：

```text
ratio = CTE_ppm / (alpha_300K × 1e6)

ratio ≈ 1    →  CTE_ppm 与曲线同为体积量，链路自洽，无需修正
ratio ≈ 1/3  →  CTE_ppm 是线膨胀、曲线是体积量，存在 3 倍不一致，需修正
```

判据要点：

- 该比值应在**大量材料上统计**后判断，单条材料可能因数据来源不同而偏离。
- 建议同时输出分布直方图，观察是否存在**双峰**（部分材料体积、部分线膨胀）——若出现双峰，说明数据来源本身混杂。
- 此脚本应在新各向异性数据集到位后**重跑一次**，作为新旧数据一致性检查的标准手段。

## 5. 张量化可行性评估

| 数据集 | 来源 | 张量化可行性 |
|---|---|---|
| `pte-reference-185-v1`（185 条） | 完整 QHA 计算，含 POSCAR 与 0–990 K 曲线 | 标准 Phonopy QHA 只输出**体积量**，方向信息天然缺失。需重做为**各向异性 QHA**（每个体积点弛豫全部晶格自由度，得到 a(T) b(T) c(T) α(T) β(T) γ(T)） |
| `nte-candidates-6701-v1-1`（6701 条） | ALIGNN 高通量**预测**集 | `manifest.property_provenance` 明示 `full_elastic_tensor: "not available for the high-throughput prediction dataset"`。**无弹性张量、无 QHA 原始输出，必须重算** |

结论：6701 条 NTE 候选要支撑各向异性，**没有捷径，必须重算**。这直接决定了新数据集的生产成本，建议尽早评估计算预算。

## 6. 新各向异性数据集验收清单

数据集交付时，除文件本身外需一并提供以下定义（决定 schema 中每温度点存几个数）：

1. **晶系**：显式字段，或由 POSCAR 推导的规则。
2. **分量顺序**：给出 `α₁₁ α₂₂ α₃₃ α₂₃ α₁₃ α₁₂` 中的哪几个、以何顺序。
3. **坐标系**：相对晶轴 `(a, b, c)` 还是笛卡尔系。
4. **单斜/三斜**：除张量分量外，是否同时给出**随温度变化的晶格角**——这两类晶系主轴随温度转动，仅存主轴值会丢失信息。
5. **量纲**：体膨胀 α_V 还是线膨胀分量；单位 `1/K` 还是 `ppm/K`。
6. **降级规则**：缺失张量数据的材料如何退回标量 α_V。
7. **与旧数据的映射**：若能给出 `CTE_ppm` 与新张量 `tr(α)` 的对应关系，可直接判定第 3 节的体积/线膨胀悬案。
